## 移植清单（按价值排序）

> **状态（2026-11-08 C 批）**：#1 音量弧＋#2 压制/归还已实现并真机验证（evdev 注入＋sysfs 帧读取：弧中压制 speaking、过期归还最新帧、Mute 清弧即时红环——有意偏离上游的弧优先序，隐私反馈主权）；固件 `00e09e3`。#5 链路三态维持现状（SUSPECT 归后续诊断批次）。

1. **音量弧（Volume arc）——用户点名的缺口**
   - 行为：青色（Cyan）弧、12 灯中亮 N 个∝音量、**2 秒窗口**
     （`volumeLEDSecs`）、仅物理按键触发（设备本地，不经网络）。
   - 关键细节（上游踩过的坑，2026-07-25 教训＝今天用户报的同款病）：
     窗口过期是 **mute-aware** 的——静音时归还红环而不是交还底层
     （`volume.go:177`）；动画进行中被压制时仍持续记 `baseLEDs`，
     归还时画的是**最新帧**，下一 tick（≤80ms）无缝续播。
2. **优先级阶梯＋压制/归还机制**
   - 上游六层：音量弧 > 静音红环 > 链路态（橙正弦＝断连/白慢闪＝待批）
     > 回合/媒体动画 > 方向覆盖 > 熄灭。低层被压制时**仍记录状态**，
     过期后正确交还（`server.go:381`）。
   - 我们现状：固件已有优先序（muted>error闪>speaking>music>thinking>
     wake闪>listening>idle，G4 定）但无"压制期记录＋最新帧归还"机制；
     移植该机制后音量弧/链路态才可能不撕裂底层动画。
3. **五条设计原则**（原文档 §1，全条照搬）：不显示系统兑现不了的状态；
   反馈本地/决策远端；一个信号一个含义；每个临时态必收敛（TTL 死人
   开关）；设备主权态永不被网络覆盖（mute 是典型）。
4. **链路三态**（LINKED/SUSPECT/DOWN）——我们已有对应雏形（断线暗白
   P4），SUSPECT 态留 C 阶段诊断批次再议。

## 不移植（有意排除）

- 场景色动画指令集（solid/spin/rotate/pulse/meter）——v0 协议走
  `assistant_state` 语义帧，呈现归固件调色板（G4 定），不回退到
  上游"控制器逐帧指定"模型。
- 方向覆盖（listening 环上的波束角度增亮）——依赖波束成形方向数据，
  D 阶段全双工后再议。
