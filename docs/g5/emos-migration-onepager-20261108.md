## 2. 缺口清单（五问＋LED 移交）

| 问题 | 答案 |
|---|---|

## 3. 三问

**3-1 core 在哪（装完后的完整对话路径）**：分两步走，emOS 是前提、C 阶段是目标——
- **emOS 装机阶段（本页范围）**：设备＝音频组件（含设备侧 AEC）；hm-core 仍在 Mac（过渡）。路径：mic→固件（逐麦 AEC→融合）→WiFi→Mac core→GLM/火山/ASR 云 API→TTS 回传→PCM 播放。此阶段 Mac 只是开发座＋调试，**不是终态**。
- **C 阶段（既定方向，HANDOFF §9）**：hm-core 上音箱（与音频组件同机、v0 回环）——音箱上跑大脑＋AEC＋音频；ASR/LLM/TTS 全云 API；**Mac/NAS 退场，家里只有音箱**。emOS 正是为这一步扫清平台障碍（无 Android 抢占、482MB 内存大部分空出）。若 C 阶段未完成前谈"取消"，如实说：未达成，仍依赖 Mac。

**3-2 固件怎么升级（无 adbd）**：
- **OS/init 镜像**：emOS 自带网络更新机制（controller 重建镜像→设备拉取→init 保底回滚，上游 0.10 起实测支持）。
- **hm 固件（音频组件）**：**网络拉取＋A/B 槽**——沿用现机制（audio_a/audio_b＋current 符号链接＋快退换槽），由 core（C 阶段后＝本机 core）经 WiFi 写非活跃槽、翻链接；ACM 串口仅调试/兜底（16MiB@115200≈23 分钟，不作为常规通道）。回滚触发：A/B 快退×3 自动换槽（已有）＋ init 层 OS 级 known-good（更深层兜底）。
- 触发与验证全部走北向 v0 协议＋串口日志，不依赖 adb。

**3-3 按键语义（固件实现）**：
- **Mute(113)**：mic 静音开关——**固件侧强制**（静音即停上行 audio_chunk＝硬件级隐私，非仅软件标志）＋MuteState 帧北向＋LED 红（调色板已有 muted）；唤醒/跟随链路随静音如实停摆。
- **音量(114/115)**：软件增益律 level±8＋持久化＋VolumeReceipt 北向（已实现并实测）。
- **长按**：v1 不做破坏性本地动作——长按事件如实上报北向（Button 带 hold 语义），由 core 决策（未来可定义＝WiFi 配置模式等）；不做恢复出厂类高危本地语义。

## 4. 安装方案概要（点头后执行）

①构建：emos-v0.10@`6a7f6625`＋两 patch（去 cache 裸写/tmpfs boot-trail），钉版 docker NDK，**显式 `aarch64-linux-android21-clang -static -O2`**，官方 packer（system_part=13＋em-wifi），**输入＝本机 p10（fa5e512c…）**，产源码 SHA＋镜像 SHA 入档；②TWRP 内 dd（§1 已演练同路径）；③首启后 `pcmprobe` 实测 64 位原生 ALSA 路径（不通回退 armv7 构建）；④固件适配（DAPM bring-up 内置、按键直读、AEC 管线＝逐麦 speex→ch0-6 融合→单路上行、exec 链接入、server_b 槽留官方版兜底）。**上行刻度因 AEC 改变，VAD −42/−47 须重标**（AEC 输出电平≠现混合电平）。
